# Book Rental Service Video Prompts

이 문서는 `Book Rental Service Demo` 프로젝트로 RAG 기반 캐싱 데모 영상을 찍을 때 바로 사용할 수 있는 프롬프트 모음입니다.

목표:
- 1차 실행에서 `F2 캐시 + RAG 컨텍스트 활용` 흐름을 보여준다.
- 2차 실행에서 `F1 세션 캐시 hit`를 보여준다.
- 시청자가 파일 경로를 몰라도 이해할 수 있게 기능 중심 질문만 사용한다.

## 촬영 전 준비

- 같은 저장소 경로에서 실행한다.
- 같은 adapter와 같은 모델을 유지한다.
- 사전 적재 후 git HEAD를 바꾸지 않는다.
- 1차 촬영과 2차 촬영 사이에 프롬프트 문장을 수정하지 않는다.

## 사전 적재 프롬프트

### 사전 적재 1

```text
이 프로젝트에서 연체료는 어떻게 계산돼?
연체 알림 메시지는 어디서 만들어져?
사용자에게 보여줄 수 있는 대여 가능한 책은 어떤 조건으로 걸러져?
```

### 사전 적재 2

```text
책 반납 처리에서 연체 일수와 연체료가 어떻게 연결되는지 설명해줘.
연체 알림에 책 제목과 연체료가 어떤 식으로 들어가는지 설명해줘.
현재 대여 중인 책 상태를 요약하는 방식도 같이 정리해줘.
```

### 사전 적재 3

```text
이 프로젝트의 책 대여 흐름을 짧게 훑어줘.
연체된 대여 건을 찾는 기준이 뭐야?
연체 알림을 보내기 전에 어떤 데이터를 읽는지도 설명해줘.
```

## 본 촬영 프롬프트

### 1차 실행

```text
이 프로젝트에서 연체료는 어떻게 계산돼?
연체 알림 메시지는 어디서 만들어져?
반납 처리와 연체료 계산이 실제로 어떻게 이어지는지 설명해줘.
마지막으로 운영자 입장에서 가장 중요한 동작을 한 문장으로 정리해줘.
```

예상 결과:
- 첫 번째와 두 번째 질문은 사전 적재와 동일해서 `F2 캐시 hit` 가능성이 높다.
- 세 번째 질문은 새 질문이지만 기존에 저장된 반납, 연체료, 알림 맥락을 활용해 `RAG`가 개입할 가능성이 높다.
- 화면상으로는 일부 task가 빠르게 생략되고, 새 task만 더 깊게 처리되는 흐름이 보인다.

### 2차 실행

```text
이 프로젝트에서 연체료는 어떻게 계산돼?
연체 알림 메시지는 어디서 만들어져?
반납 처리와 연체료 계산이 실제로 어떻게 이어지는지 설명해줘.
마지막으로 운영자 입장에서 가장 중요한 동작을 한 문장으로 정리해줘.
```

예상 결과:
- 동일 프롬프트 재실행이므로 `F1 캐시 hit` 가능성이 높다.
- 세션 전체가 재사용되어 1차 실행보다 훨씬 빠르게 끝난다.
- 영상에서는 이 장면이 가장 직관적인 캐시 절감 장면으로 보인다.

## 촬영 중 강조 포인트

- 1차 실행: "익숙한 질문은 바로 재사용되고, 새 질문은 과거 맥락을 활용해 답한다"
- 2차 실행: "이번에는 전체 세션 결과를 그대로 재사용해서 더 빠르게 끝난다"
- 프롬프트 안에서는 토큰 절감 같은 내부 용어를 굳이 말하지 말고, 화면의 `cache hit`와 응답 속도로 보여준다
